  <action>
Create `cmd/adoBizInt/flags.go` with one function that constructs a `flag.NewFlagSet` for a given
subcommand and registers the global flags into it: `--json` (bool), `--timeout`
(`flag.DurationVar`) and `--project` (repeatable or comma-separated string). Registering them
through one shared function is the point of D-20 — stdlib gives no compile-time check against
eight independent declarations, and the drift it prevents is `prs list` accepting `--timeout`
while `releases approvals` silently does not.

Construct every FlagSet with `flag.ContinueOnError`, call `fs.SetOutput(os.Stderr)` explicitly,
and replace `fs.Usage`. Stdlib's default `ExitOnError` prints usage and exits 2, which is now
auth failure and would be a lie (D-22). `SetOutput` is explicit rather than relying on the
default so a future change cannot silently redirect flag errors to stdout and break OUT-03 —
RESEARCH.md logs this as assumption A2 and asks for a test rather than trust.

A flag parse error returns 3 with usage on stderr and nothing on stdout (D-09).

Wire `--timeout` only as far as parsing and carrying the value in this plan. Plan 03-05 owns
applying it, because the override must land after `cfg.Validate()` to avoid tripping
`config.go:159`'s `FetchTimeout <= PollInterval` check.

Wire `--project` only as far as parsing and carrying the value in this plan. Plan 03-04 Task 2
owns applying it — it is passed as the `projects` argument of each read method, and the choice of
what an unset flag means is settled there, not here. Registering it in the shared registrar
without a consumer would leave a flag the CLI accepts and ignores, so 03-04 Task 2 is a hard
dependency of this flag being honest.

Create `cmd/adoBizInt/usage.go` with the three hand-written usage levels (D-21, CLI-05):
top level lists the six nouns; noun level lists that noun's verbs; verb level prints the
FlagSet's own flag list. Each level is discoverable from the one above. Sort noun and verb
listings so output is deterministic across runs.

Handle `--help`, `-h` and the bare-noun case **before** `config.Load` and `cfg.Validate` in
`run()`. `Validate` aborts when `PAT` is empty, so `adoBizInt --help` failing because no PAT is
configured would be hostile and is a real trap confirmed at `config.go:151`. Help exits 0; a bare
noun with no verb exits 3 (03-01 Task 1 already established this).
  </action>

Create `cmd/adoBizInt/render.go` emitting plain text for each of the eight payload types. Do not
import anything from `internal/ui` — the responsibility map forbids it, and lipgloss ANSI escapes

stdout and the renderer does not run.
