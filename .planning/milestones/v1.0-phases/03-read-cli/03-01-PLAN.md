<planner_decisions>
Discretion items settled here, to be cited by later plans:

- **D-P1 — the dispatch seam type.** The dispatch table is keyed on `noun verb` and stores a
  closure over an unexported `readClient` interface declared in `package main`
  (consumer-side interface, Go convention). `*ado.Client` satisfies it structurally with no
  change to `internal/ado`. This resolves PATTERNS.md cross-cutting risk 1: the Phase 1 fake
  seam (`&ado.Client{gitClient: fake}`) uses unexported fields and cannot be constructed from
  `cmd/adoBizInt`, so CLI failure-path tests satisfy `readClient` with a hand-written fake
  instead.
- **D-P2 — the closure signature absorbs `GetBranches`' extra parameter.** `GetBranches` is the
  only read taking `(ctx, projects, repositories)`. Each dispatch entry is its own closure, so
  no uniform method signature is required and no adapter is needed.
- **D-P3 — `items` and `failures` are pre-allocated in `newResult`.** Both marshal as `[]`.
- **D-P4 — the payload is marshalled to `[]byte` then written with one `os.Stdout.Write`.**
  Never `json.NewEncoder(os.Stdout).Encode` — a streaming encoder can leave a partial document
  ahead of the 03-05 crash record (D-23).
</planner_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell → `cmd/adoBizInt` | `os.Args` is caller-controlled and reaches the dispatch key and flag values |
| process → stdout | Machine-parsed by an agent; any non-JSON byte is a parse failure |
| `config.Config` → error/diagnostic paths | The struct carries the PAT |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information disclosure | error and diagnostic paths in `run()` | high | mitigate | Diagnostics use `fmt.Fprintf(os.Stderr, "...: %v", err)` on the error value only; never format the `config.Config` value or the client. Acceptance criterion greps `cmd/adoBizInt/` for stdout writers. |
| T-03-02 | Tampering | `os.Args[1]`/`[2]` as the dispatch key | medium | mitigate | The key is looked up in a fixed map of eight literal `noun verb` strings; an unmatched key returns 3 and never reaches a client call. No string is passed to a shell or a query. |
| T-03-03 | Spoofing | a partial read presented as complete | high | mitigate | The exit mapper scans for `FailureAuth` first and `!complete` second, so no failing read can exit 0 (D-05, D-07). Asserted by the Task 2 table. |
| T-03-04 | Repudiation | stdout carrying a partially written document | medium | mitigate | Single `json.Marshal` + single `os.Stdout.Write` (D-P4). No streaming encoder in `cmd/`. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install occurs in this plan or this phase; D-19 locks stdlib `flag` and forbids new dependencies. `go.mod` is unchanged. |
</threat_model>
