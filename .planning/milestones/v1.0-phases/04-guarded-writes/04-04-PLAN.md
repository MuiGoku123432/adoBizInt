  <behavior>
    `TestWriteGuardMatrix` ranges over the keys of `writeSupportByCommand` and, for each
    key, runs a subtest asserting all five guards:
    - no `--confirm` → mutating fake func (nil) never called; exit 0; `executed:false`; `outcome:"dry_run"`.
    - `--confirm` with an empty diff → exit 4; `outcome:"no_op"`; `changes` marshals as `[]`; audit file zero-length.
    - `--confirm` with a real diff and a nil mutate error → exit 0; `outcome:"executed"`; exactly one audit line.
    - `--confirm` with `context.DeadlineExceeded` → exit 5; `outcome:"unknown"`; exactly one audit line with `"outcome":"unknown"`.
    - unwritable audit sink with BOTH fake funcs set → mutating func never called; exit non-zero.
    A key with no entry in the subtest fixture table fails with `t.Fatalf`, so adding a
    seventh verb without a fixture fails the suite.
  </behavior>
  <action>
    Add `TestWriteGuardMatrix` to `cmd/adoBizInt/write_test.go`. It must iterate
    `writeSupportByCommand` — the same map the dispatcher and `newFlagSet` consult — not a
    literal slice of verb names. Pair it with a `map[string]writeFixture` supplying, per
    verb, the argv that produces a diff, the argv that produces a no-op, the pre-read fake
    return values for each, and which `fakeWriteClient` func is the mutating one. On a
    command key with no fixture, `t.Fatalf("command %q is not covered by the write guard
    matrix")` — this is the drift guard and it mirrors the existing `filter_test.go`
    coverage guard at :311-349.

    Prefer the nil-func-field mechanism over any call counter for the no-mutation
    assertions: a counter asserts equality with zero after the fact, while a nil func field

    failure.

    guarantee.
