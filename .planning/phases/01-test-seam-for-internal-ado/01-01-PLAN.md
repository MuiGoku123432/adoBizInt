<assumption_delta_decision>
**Primary noun:** the assignable unexported field on `ado.Client`, not a
constructor.

**Decision:** `no-change`.

**Rationale:** The ROADMAP's provisional plan title 01-02 ("Add an injectable
constructor alongside the existing `NewClient`") is superseded by D-09.
Add-alongside was never the right frame here because there is no general
representation to promote: in Go, an unexported struct field is *already*
injectable from an in-package test, so the seam exists the moment the field type
becomes an interface. A `NewClientWithAPIs` would have to export the interfaces
(reversing D-05) and would add permanent public API with zero production
consumers. Independently, `NewClient` performs network I/O at `client.go:70`, so
no constructor signature could have made it testable anyway (RESEARCH Pitfall 4).

This is not accepted debt — nothing is deferred. SEAM-02 is satisfied in full by
field assignability; D-10 records that traceability explicitly so
`/gsd-verify-work` does not read the absent constructor as a gap. REQUIREMENTS.md
wording is deliberately left unamended.

**Suggested (not required) invariant test:** none. The invariant "a `Client`
literal with fakes drives real methods" is already load-bearing in every test
this phase writes; a dedicated test would be tautological.
</assumption_delta_decision>

<reversibility>
| Decision | Rating | Rationale |
|----------|--------|-----------|

| Interfaces in their own file (RESEARCH A1) | reversible | File move; no import or symbol change. |

No `one-way` decision in this plan. No `checkpoint:decision` task.
</reversibility>
