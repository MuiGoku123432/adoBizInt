<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TUI user to release approval and pipeline queue | Release approvals are change-management gates (SOX); a queued run consumes build capacity and may deploy. |
| Release comment text to ADO and to audit.jsonl | User-entered free text; it belongs in ADO, not the audit file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-19 | Tampering | approval or queue sent on input submit without a diff confirm | high | mitigate | Submit only starts the flow; y on the diff modal is the only path to Execute (TestApproveSubmitPreviewsThenConfirms, TestQueueEscSendsNothing). |
| T-07-20 | Repudiation | approval or rejection with no audit record or wrong actor | high | mitigate | guard.Run appends the record with actor tui (asserted in both tracer tests); an unwritable sink blocks the write (shared flow, 07-04). |
| T-07-21 | Information Disclosure | release comment persisted into audit.jsonl | low | mitigate | The comment is passed only to the ADO mutation; TestApproveSubmitPreviewsThenConfirms asserts the record line does not contain it. |
| T-07-22 | Tampering | approve sent after someone else already acted on the approval | medium | mitigate | The guard's pre-read refuses a no-op (TestAlreadyApprovedReleaseIsNoChange), and Execute refuses a changed diff (07-04 approves()). |
| T-07-SC | Tampering | npm/pip/cargo installs | low | accept | Not applicable: no package install, and go.mod and go.sum are untouched. |
</threat_model>
