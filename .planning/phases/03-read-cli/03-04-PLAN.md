  <behavior>
    - An empty query keeps every item.
    - A whitespace-only query keeps every item, because the existing code trims before testing.
    - A query matching a substring of any one supplied field keeps the item.
    - Matching is case-insensitive in both directions: an upper-case query matches a lower-case field and the reverse.
    - A query matching none of the supplied fields drops the item.
    - For workitems and prs, a numeric ID substring matches, because the caller formats the ID into the field list.
  </behavior>
  <action>
Add a shared matcher to `internal/ado/filters.go` that takes the already-normalized query and a
variadic list of the item's searchable field strings, and reports whether any contains the query.
This is closer to what the code already does than a type-switching `MatchesSearch(item any, q string)`,
which is the trap RESEARCH Pitfall 5 names: five call sites with five field sets collapse into a
type switch if you force one signature.

Because `workitems` and `prs` both search a numeric `ID`, the caller formats it into the field list.
The matcher itself takes strings only.

Rewire all five `buildRows()` bodies to normalize the query once —
`strings.ToLower(strings.TrimSpace(m.searchInput.Value()))`, which is already byte-identical in all
five files — and pass it plus that view's field list to the matcher. **Each view must pass exactly
the field set listed in the source-corrections table and no more.** Adding a field to any view is a
behavior change CLI-01 forbids.

Three mechanical traps confirmed in the source, do not trip them:
- `branches.go:331` uses `for i, item :=` and consumes the index downstream; the other four use
  `for _, x :=`. A blind five-file substitution breaks this one.
- The receiver field name differs: `m.items` in workitems/prs/branches, `m.releases` in releases,
  `m.runs` in pipelines. There is no uniform loop to template.
- `branches.go` inlines `strings.ToLower` inside `Contains` rather than hoisting to locals like the
  other three. Normalizing this is cosmetic and safe, but it must not change which fields are read.

Extend `internal/ado/filters_test.go` with the behavior-block rows for the matcher, written before
the implementation.

Add ordered-row equivalence tests for `branches`, `releases` and `pipelines` in the same shape as the
two written in 03-03, and extend the existing `workitems` and `prs` row tests with search cases.
Every one asserts the full ordered `[]table.Row`.

  <action>
Register the filter flags on the subcommands whose payload type supports them: `--search` on the
five verbs with a searchable payload, `--assigned-to-me`, `--hide-done` and `--hide-tasks` on
`workitems list`, `--repo` on `prs list` and `branches list`. `--project` is already a global flag
from 03-02.

Apply the promoted predicates to the result's `Items` slice after the read returns, before
serialization. Filtering after the read means the failure list and the `complete` flag continue to
describe the read itself, which is what the exit-code contract keys on.

**Every filter flag defaults to off** (D-18). The workitems TUI defaults `assignedToMeFilter` and
`hideDoneFilter` to true because that is the useful human view, but a CLI that hides data the
caller did not ask to hide is the exact failure this project exists to prevent: an agent running
`workitems list` and silently receiving a filtered subset would see `complete:true` while the item
list is not the whole picture. The empty-slice-means-match-all rule preserved in 03-03 gives this a
free implementation — the CLI passes empty slices.

Do not read filter defaults from config. The same command must return the same data on two
machines; config-driven defaults are hostile to agent reproducibility.

For `--assigned-to-me`, resolve the identity from the client's cached `CurrentUserEmail()`. Phase 1
D-12 leaves identity resolution non-fatal, so the cache can be empty. When it is, the promoted
predicate is a no-op by design (03-03 Task 1); emit a one-line warning to stderr saying the filter
had no effect because the identity is unavailable, so the caller is told rather than silently
receiving an unfiltered list they believed was filtered.

Add tests over the injectable writers asserting: no filter flags returns every fixture item;
`--hide-done` drops the done ones; `--assigned-to-me` with an empty cached identity returns every
item AND writes a warning to the stderr buffer.
  </action>
