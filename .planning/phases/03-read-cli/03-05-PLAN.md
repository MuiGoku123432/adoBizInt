<planner_decisions>
Discretion items settled here:

- **D-P5 — `--timeout` maps to `FetchTimeout` only.** That is what "per-invocation deadline" means
  in CLI-04 and it is the budget an agent cares about. `RequestTimeout` is baked into
  `connection.Timeout` at client construction, which happens before a flag value could apply cleanly.
- **D-P6 — the override is applied after `cfg.Validate()`.** `config.go:159` rejects a
  `FetchTimeout` at or below `PollInterval` (default 30s), so writing `--timeout 10s` into the
  config before validation fails with a message about a TUI refresh concept that has no meaning on
  a one-shot read.
- **D-P7 — `fetchctx` gains `NewWithParent(parent, budget)` and `New` delegates to it with
  `context.Background()`.** The alternative — a CLI-local `context.WithTimeout` — duplicates the
  zero-budget default that exists precisely to prevent an unbounded read, reintroducing the failure
  the package was written to remove.
</planner_decisions>

with a single `os.Stdout.Write`, consistent with 03-01's D-P4 rule.

convention. Not 0: a script interrupting its own child could not distinguish "interrupted, no

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| panic value → stdout | The recovered value and anything derived from it is machine-parsed |
| Go runtime stack → any writer | Stack frames print function arguments, including `config.Config` carrying the PAT |
| OS signal → process | An external interrupt terminating an in-flight read |
| log file on disk | `~/.config/adoBizInt/adoBizInt.log` receives the full stack |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Information disclosure | crash record on stdout | high | mitigate | The record carries the panic message and the log path only; no stack trace (D-24). Asserted by a test that the stdout record has no stack field and contains no substring of a PAT fixture value. |
| T-03-15 | Information disclosure | full stack written to the log file | medium | mitigate | The stack goes only through `logging.Logger()`, which opens the log with mode `0644` at `logging.go:24`. The stack may contain the PAT, so the log is a credential-bearing artifact; recorded here as a known exposure. Tightening the log file mode is a Phase 5 hardening candidate, not this phase's change. |
| T-03-16 | Spoofing | a panic or interrupt read as an empty result | high | mitigate | The record is a distinct top-level `error` object, never a `Result[T]` (D-26), and both paths exit 3. Asserted by an exact-top-level-key-set test. |
